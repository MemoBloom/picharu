# 双看板三阶段实施与验收

目标：用户个人控制台和管理员完整产品复盘看板。实现位于Web仓库，基线228e157，分支feat/console-analytics。产品范围见工作区docs/product/USER_CONSOLE.md、ADMIN_CONSOLE.md和ADMIN_ANALYTICS_SPEC.md；后者的24项指标及8类页面保留为最终验收范围，不能以权限/列表完成代替看板完成。

## 阶段1：权限、事实与采集契约

- 服务端受控管理员角色及每次查询复核；默认无管理员，自助注册不能提权。普通浏览器不能直接读写管理/事件表。
- 业务事实仍以任务、账本、订单、Worker记录为准；新增环境标记和上传完成时间。历史环境未知，不自动冒充正式/测试数据。
- 显式POST下载在验证本人成功结果并签URL后记录服务端保存行为；GET兼容路径不计保存。曝光/选择/查看/评价为低信任浏览器事件，服务端检查关联关系、时钟、大小和业务幂等。
- 开关默认关闭，采集启停区间可追溯；不把迁移安装时间或历史GET下载当作已采集区间。采集失败不能重放收费任务；下载失败和采集失败分别报告。
- 只追加审计，敏感读取必须有审计；不会通过网页授予角色或执行资金写操作。

验收：真实SQL权限、跨用户、撤权、幂等/冲突、删除/过期、签URL失败、采集缺失、时钟、禁用；契约/OpenAPI/类型/基础回归/生产构建。并发不以单连接PGlite替代PG独立连接。

## 阶段2：用户个人控制台

- 本人总览、余额/预留、30天状态汇总、最近作品与付款入口。
- 稳定分页积分流水，消费/预留/释放分开；本人任务按工具/状态/时间筛选，集中作品视图复用原下载/继续编辑/删除能力及保留期。
- 日语界面沿用既有品牌规范；空数据、故障、账户限制及账户切换分别处理。

验收：两用户隔离、稳定分页、金额/状态与数据库一致；桌面/320px实际页面与交互；失败不展示假0。账户注销/资金写操作属于单独生命周期/财务任务，不作为只读看板的隐含前提。

## 阶段3：管理员完整数据看板

- 8类分析页面：总览、逐用户、特效、漏斗、留存、模型版本、资金/成本、运行/数据质量。
- 24项指标逐项对应数据源和成熟窗口；柱状图/趋势/热力图/特效占比及覆盖、保存行为率、版本对比；支持筛选、前期对比、同口径钻取及安全CSV。
- 未采集、未成熟、未知费用和不同币种分别呈现；新增工具/模型依赖稳定ID与快照版本，不写死20条图表。
- 浏览器埋点接入真实编辑/查看/下载路径，统计来源可追溯；反馈与观察性模型对比不能充当人工效果evaluation。

验收：口径样本覆盖跨日/时区、重复请求、0用量、多特效、取消/在途、24h/D7/W1、迟到、已删除结果、版本、跨期退款、未知成本及环境隔离；真实本地API+数据库+浏览器全链路；完整verify及必要PG并发回归。
