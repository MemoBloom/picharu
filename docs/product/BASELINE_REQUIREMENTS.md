# 首期范围统一决策：20 个工具

决策日期：2026-10-19。来源：用户明确要求从 20 个工具开始论证技术架构，原六工具范围不足以支撑后续用户需求。

## 已确认的范围约束

1. **首期产品需求与技术架构以完整 20 个工具为基线。** 原六工具 MVP 方案已被本决策取代，不能继续作为设计、估算或验收范围。
2. 架构论证必须逐项覆盖 20 个工具的输入、参数、Prompt、模型能力、输出、资产与版本、任务状态、额度计费、失败恢复、质量评测和运营指标。
3. 分批开发、集成测试或灰度仅决定执行与发布顺序，不能把后批工具的架构需求推迟到设计之外。某工具未通过质量测试，可暂缓公开，但仍保留在 20 工具设计与评测范围，并记录缺口。
4. 工具数量不等于模型数量。1–2 个商用生成端点仍是既有选型目标，但是否能覆盖全部工具需要逐项验证，不能预先假定所有功能只是替换单图 Prompt。
5. 多图合成必须进入输入协议、资产归属和供应商能力论证；局部改色、人像保持、商品与空间结构保持也必须纳入质量约束。发现能力不足时记录并评估解决方案，不通过缩减工具数量绕过。
6. 本次确认的是工具范围。JEV 推荐、连续编辑、现有云部署与支付方案属于既有设计资料，应结合 20 工具继续评审；本次同步不代表这些实现、模型质量或外部资质已经验证。
7. 用户进一步明确：**20 个效果仅为初期范围，不是长期工具数量上限；首版无需把每个效果一次做到完善，架构必须适配后续模型能力迭代。** 优先稳定工具意图、输入资产、任务与计费边界；模型端点、参数、模板与质量档位允许版本化演进。高级蒙版、分割、身份/几何控制等按实际能力逐步启用，不因未来可能需要就全部列为首版实现前置条件。20–50 个模板是初期规模规划，不应成为全库长期硬上限。
8. 用户确认开发方式：**全部由 AI 完成开发，允许多个 AI agent 并行；人工只负责代码架构设计和 evaluation。** 实现、测试工程、集成、缺陷修复与开发文档由 AI 承担；人工不作为常规编码或联调资源计入排期。执行按契约和文件所有权分工，实际同时运行数量受可用执行槽限制。后续用户已授权完整接口与 Vercel Web 后端开发，Cloud Run Worker 和 Lambda JEV 仅做设计。本轮实际交付见 [后端说明](../backend/VERCEL_BACKEND.md)。

## 验收和文档优先级

- 设计验收：20/20 工具有明确的能力映射及数据/接口影响；未知项必须显式列出，不能以六工具链路成功代替完整设计。
- 图像质量首轮计划沿用技术包：每工具 15 个授权任务用例，20 × 15 = 300；可共享源图，按任务独立评测。单模板还需按模板文档执行验证。
- 技术成功率 ≥98%、人工可接受率 ≥80% 是既有试行目标，仍待实测校准，不是本次已达成结果。旧 60 用例和较低质量门槛不再作为首期整体放行标准。
- 同一范围问题发生冲突时，本文件中的用户确认决策优先于两包历史方案；其余领域继续遵循各自决策文件，并在发现矛盾时显式统一。
- 原始 ZIP 保留为导入快照；后续阅读与实施以已同步的解压文档及本文件为准，不能用原始 ZIP 恢复旧范围。
