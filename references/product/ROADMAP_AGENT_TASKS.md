# 开发路线图与责任分工

详细计划统一见 [DEVELOPMENT_ROADMAP.md](../../docs/planning/DEVELOPMENT_ROADMAP.md)，包含 14 个责任模块、M0–M8、依赖、交付、验收与资源假设。本文件保留简版导航，原 Sprint/两周或 D0–D30 目标不再作为本轮可靠工期依据。

## 优先级

1. 真模型端点、尤其多参考图、费用与上游不确定性验证。
2. 工具/模板/模型适配/任务快照的稳定边界和版本。
3. 身份、固定资产、持久任务、积分与成本的可靠闭环。
4. 共用工作台接入 20 工具，记录各自质量与限制。
5. 模型切换、任务恢复与回滚演练，再根据数据持续改善效果。

## Milestone

| 节点 | 交付与验收重点 |
|---|---|
| M0 | 完整能力矩阵与早期真调用；未知及外部依赖如实记录 |
| M1 | 核心契约、输入角色、数据与版本、Mock、环境和责任明确 |
| M2 | 真实单图/多图代表链路，资产固定、任务恢复与积分结算成立 |
| M3 | 20 工具 Alpha、共享工作台、历史/继续编辑、逐工具接入证据 |
| M4 | 模型升级/回滚和在途任务兼容；并发与异常可恢复 |
| M5 | JEV 推荐到真实生成的闭环；推荐失败可回退目录 |
| M6 | Stripe 沙盒与积分包，支付/充值/退款/对账；实际收款条件独立 |
| M7 | 技术 Beta、Smart Edit、正式收费分开验收；真实用户反馈与成本 |
| M8 | 根据用户结果迭代模型/模板，必要时增强区域控制或专项能力 |

先做代表性链路不能替代 20 工具接入；“有页面”或“用了 Mock”也不代表实际能力已经可用。效果可以迭代，身份归属、账务幂等、可恢复交付必须保证。

## 职责与协作

用户确认全部由 AI 开发，人工只负责架构设计与 evaluation。下列职责全部由 AI 承担；详细的 8 类 agent 所有权及并行波次见 [AI_AGENT_EXECUTION_PLAN.md](../../docs/planning/AI_AGENT_EXECUTION_PLAN.md)。

- 集成：统一契约、工具 ID、状态、版本与接口变更。
- Web：共用工作台、日语工具页、结果、历史、推荐/支付 UI。
- Worker/模型：供应商适配、长任务、结果落存、恢复与运行成本。
- Auth/DB/Billing：身份、资产归属、任务/积分事务、订单和支付事件。
- Prompt/QA：模板、授权样本、逐工具质量/成本评测与版本对比。
- JEV：推荐模型与接口、候选适配和性能；不默认承担生成/分割职责。
- 产品/运营：日语内容、用户验证、经营依赖、价格及渠道记录。

按契约依赖和可用执行槽并行调度 AI；集成与修复也由 AI 负责。共享 migration、契约和同一 Prompt ID 的变更由单一 AI 所有者维护，避免互相覆盖。人工不逐项介入普通实现，集中处理架构取舍和 evaluation。

## 节点报告要求

附交付物、验证证据、真实/Mock 区分、版本与费用、已知限制、阻塞和后续项。状态分别记录未开始、进行中、部分完成/受阻、已完成。API、JEV 或支付资质未就绪时继续独立工作，不伪造已经完成的验证。
